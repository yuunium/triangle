# SANKAKU

**正七角形、つくれる？** 7つの点でぴったりを目指す、七角形専用の目測ブラウザーゲームです。

公開先: **https://sankaku.linetoslack.workers.dev/**

## 遊び方

1. トップの「正七角形に挑戦」で始めます。図形の選択や練習モードはありません。
2. 盤面をクリック／タップして、A〜Gの順に必要な数の点を配置。外周をたどる順に置いてください。
3. 置いた点はその場で確定します。ドラッグ・キーボードでの移動や1点ずつの取り消しはできません。「やり直す」で全点をリセットできます。
4. 必要な点を置いたら「採点する」で一致度を表示。この回の点と結果は確定します。
5. 採点後は一番近い正七角形を自動で重ねて答え合わせします。「もう一度つくる」ですぐに再挑戦できます。

マウス・タッチ・キーボード対応。盤面にTabでフォーカスし、矢印で次の点のカーソルを動かしてEnterで配置できます。Shift＋矢印はカーソルの微調整です。配置済みの点はフォーカス・編集できません。

## 結果画像とXへの投稿

採点後、「結果を画像でシェア」で確定した図形・一致度を含む1200×675のPNGを共有できます。ファイル共有対応の端末ではOSの共有メニューが開くので、共有先からXなどを選びます。端末や共有先によって対応状況は異なります。

「画像保存・Xに投稿」からは、結果画像のプレビュー・保存・Xの投稿画面を利用できます。**画像を保存し、Xの投稿画面で添付してください。** 本文・一致度・その形へのリンクは入力済みで開きます。Web Intentへ画像を自動添付したと誤表示しません。XアカウントのAPI認証・メディアのサーバーアップロード・自動投稿は行いません。

画像はブラウザー内で生成し、外部へ自動送信しません。ネイティブ共有をキャンセルしても投稿やダウンロードを勝手に続けません。ゲームのルートURLを共有します。以前の`?sides=3`などのリンクも七角形の入口になり、開始時に古い形のパラメーターを取り除きます。

## ローカル開発

Node.js 22.17以上を使用します。

```sh
npm ci
npm run dev
```

```sh
npm test                 # 採点・共有・ランキングAPI/SQLのテスト
npm run build            # ランキングなしの静的版 / Sites互換ビルド
npm run build:cloudflare # ランキング付き静的アセットを dist/client に出力
npm run dev:cloudflare   # ローカルのWorkers / D1を起動
```

React + Vite。アイコンと日本語フォントもビルドに同梱されます。`npm run dev`はゲーム単体の開発用でランキングを表示しません。ランキングまで試す場合は初回に`npx wrangler d1 migrations apply sankaku-ranking --local`を実行し、`npm run build:cloudflare`の後に`npm run dev:cloudflare`で起動します。

## Cloudflareへの公開

ゲームの静的アセットと同じオリジンのランキングAPIを1つのWorkerで配信します。`wrangler.jsonc`にWorker名・D1の接続・連投制限を定義しています。APIや認証の秘密鍵をフロントへ埋め込みません。

```sh
npx wrangler login
npm test
npx wrangler d1 migrations apply sankaku-ranking --remote
npm run deploy:cloudflare
```

精密値追加の移行後、既存データは`node scripts/backfill-score-raw.mjs --remote`で保存済み座標から再計算して補完します。表示用点数・名前・日時・順位は変更しません。未補完の行だけを対象にするため再実行可能です。ローカルD1では`--remote`を外します。

Cloudflareのデプロイは上記コマンドで実行します。GitHub連携の自動デプロイは設定していません。WranglerのOAuth認証はPC側に保存され、リポジトリへコミットしません。

以前の`https://yuunium.github.io/triangle/`は新サイトへ移動するページです。`.github/workflows/pages.yml`がmainへのpush時にテストして`npm run build:pages`の出力`dist/pages`を公開します。形を指定するクエリは維持します。テンプレート由来の`worker/`と`.openai/`はSites互換用として残し、Cloudflare本番の処理は`cloudflare/index.mjs`に分離しています。

## 独自ドメインの接続状況

公開先として`https://sankaku.yuunium.jp/`を選択し、Cloudflareの無料ゾーンとWorkerへのカスタムドメイン設定は追加済みです。2026年10月31日時点では、XServerのネームサーバー変更の最終確認待ちで、公開DNSはまだ切り替えていません。切り替え先は`gemma.ns.cloudflare.com`と`yevgen.ns.cloudflare.com`です。XServerの「DNSレコード設定」にNSを追加する操作ではなく、「ネームサーバー設定」で指定します。

既存の`ganryo-server`、`nachibutton`、`pazzcolla-redirect`は、自動スキャンでは見つからなかったため、XServerの設定画面から接続先を引き継いでCloudflareへ追加しました。3件ともDNSのみ・TTL300秒です。既存のGoogle所有確認用TXTも保存しています。旧ネームサーバーのSOA・NSは移行対象に含めません。

カスタムドメインはダッシュボードで管理しています。DNSとHTTPSが確認できるまでは、既存のworkers.devとGitHub Pagesの転送先を維持します。親の`yuunium.jp`へ同じゲームを公開する設定は追加していません。AdSenseの登録単位と親ドメインの確認ファイル配信については、ゲームの公開先とは分けて設定内容を確認します。

## 採点

nを角の数、面積をAとして、以下を計算します。

```text
一致度 [%] = 100 × 4tan(π/n) × A / 各辺の長さの2乗の合計
```

位置・大きさ・回転・鏡映には依存しません。選んだ正多角形は100%、一直線または全点が重なる場合は0%。辺が交差している場合も0%です。三角形では従来の`4√3 × A / (a²+b²+c²)`と同じで、直角二等辺三角形は約86.60%です。正方形モードの2:1の長方形は80%になります。

表示は小数点以下2桁。完全一致と区別するため、100%未満の値が丸めで100.00%になる場合は99.99%と表示します。浮動小数点誤差の許容範囲はスコアで1e-10です。

採点後の点線は、重心を保った最小二乗の正多角形です。これはずれを見比べるためのガイドで、採点式そのものとは別です。辺が交差した図形や一直線の図形ではガイドを無効にします。

## 七角形ランキング

採点はReactに依存しない`src/geometry.mjs`にまとめ、Cloudflare Workerとブラウザーで同じモジュールを使用しています。`SCORING_VERSION`は`regular-polygon-q-v1`です。既存の`evaluateTriangle`と`fitEquilateral`も互換用に残しています。

七角形の採点後、ニックネームを入力して明示的に登録します。名前・一致度は公開情報です。D1には照合用の点座標・採点バージョン・記録日時も保存します。登録前の点はサーバーへ送信しません。

`POST /api/rounds`で30分有効の回を発行し、`POST /api/scores`でその回を1度だけ登録、`GET /api/leaderboard`で上位50件と自身のベストを取得します。HttpOnly・SameSiteのCookieでブラウザーを区別し、自己ベストを1件記録します。Cookie削除や別端末への変更では同じ利用者として認識しません。下がった点数や同じ点数では既存のベスト・名前を更新しません。

送信された点数は信用せず、座標から再計算します。表示と同じ小数点以下2桁のスコアで順位を付け、同点は同順位にします。回の所有者・期限・採点バージョン・座標・名前・同一オリジンを確認し、重複送信は冪等に処理します。IP単位で読み込み120回/分、書き込み20回/分を目安に制限します（Cloudflare拠点単位の近似制限）。期限切れの回は新しい回の開始時に削除します。

`rounds.score_raw`と`records.score_raw`には計算した一致度を丸めずREAL値で保存し、小数第10位を含む精度を残します。従来の`score`列は表示・順位用の小数2桁として維持します。精密値は公開APIへ追加せず、将来の利用に備えて内部で保持します。既存の自己ベスト更新・同点ルールは表示値基準のままです。

座標の自動生成やCookieを使い分けた別人登録までは完全に防げません。ログイン不要のカジュアルなランキングです。APIはプレイヤー識別Cookieや回のトークンをランキング一覧へ公開しません。

## AdSenseの導入準備

ユーザー提供の`pub-1749432130339656`を`public/ads.txt`と`index.html`の所有確認メタタグに設定しています。`/ads.txt`はGoogleが指定する1行をプレーンテキストで返します。`/privacy.html`には現在のランキング・Cookie・画像共有と広告準備状況を記載し、フッターから新しいタブで開けます。

現在は所有確認のみで、広告スクリプトも広告枠も有効にしていません。AdSenseの「サイト」で、登録したサイトURLに対して「ads.txtコードスニペット」または「メタタグ」で確認し、審査をリクエストします。workers.devは公開サフィックスですが、現在のURLはその下にさらにWorker名が付くため、AdSenseが登録したドメインと確認対象URLが一致するか管理画面で確認してください。URLが受け付けられない場合は、所有する独自ドメインなどへ接続してから申請します。

広告表示の次の作業は、AdSenseの「広告 → 広告ユニット単位 → ディスプレイ広告」で取得したコード（`data-ad-slot`を含むもの）の反映です。自動広告は無効のまま、ランキングより下に手動の広告枠を置き、ゲーム操作との距離を確保します。表示開始前に、サイトの承認、Googleの「プライバシーとメッセージ」で必要な地域の同意設定、実際の広告事業者に合わせたプライバシーポリシーの更新を行います。

参考: [サイトの追加・所有確認](https://support.google.com/adsense/answer/12169212?hl=ja)、[広告ユニットの作成](https://support.google.com/adsense/answer/9274025?hl=ja)、[必須のプライバシー開示](https://support.google.com/adsense/answer/1348695?hl=ja)、[ゲームと広告の配置](https://support.google.com/adsense/answer/2768340)、[同意管理の要件](https://support.google.com/adsense/answer/13554116?hl=ja)。
