# Prototype Instructions

## Project decisions

- GitHub repository: https://github.com/yuunium/triangle. Primary deployment is Cloudflare Workers at https://sankaku.linetoslack.workers.dev/, with D1 for rankings. The user authorized migration and Workers/D1 creation and updates. GitHub Pages is a redirect preserving the shape query. Preserve relative asset URLs.
- Selected visual: latest option 1, warm white canvas, orange geometry, charcoal action button. Use restrained Japanese sans-serif typography and generous space. User subsequently requested removing the background dot grid; keep the board plain.
- Preserve the heptagon-only loop: place seven points in perimeter order, explicitly score, then freeze that round. Every placed point is immediately fixed: no dragging, keyboard movement, or single-point undo, including before scoring. Keyboard arrows move only the next-point cursor. Restarting begins a new round.
- The user removed all other shapes. Offer only "正七角形、つくれる？" and the primary seven-point start action; no shape picker or practice list. Ignore old sides parameters and remove them when starting. Share only the root URL. Keep SANKAKU branding. Generic geometry helpers may remain internal for compatibility/tests, but must not enable other game modes.
- Restart immediately with the same shape, without asking again. Always show the nearest regular polygon after each valid score. The user removed the ideal-overlay checkbox; do not add a hide/show control. Keep invalid-shape overlays suppressed.
- Keep the gameplay title free of explanatory paragraphs beneath it; the user removed those short instructions. Do not retain blank space where they were. Keep placement accessibility instructions on the board and rules in the scoring help.
- On the scored phone screen, keep replay and the nickname/ranking-registration form visible together without scrolling at 320×568 and 390×660 content viewports. The user explicitly rejected shrinking the figure: preserve the 300px mobile drawing board and figure scale, and save space through the surrounding headings, whitespace and control layout. Use the shape label/score without a repeated visible result heading, a full-width replay button and an inline named ranking action before sharing. Keep headings accessible to screen readers. Scroll to the top after scoring; keep share tools and the leaderboard further down.
- Result sharing stays static: generate a PNG locally, offer native file sharing where supported, and provide PNG saving plus an X composer link with clear manual-attachment instructions. Do not add API secrets or automatic posting.
- Apply Emil Kowalski's design-engineering principles: immediate point placement, 120ms press feedback, brief purposeful result transitions, keyboard and reduced-motion support.
- The interactive geometry is functional canvas graphics, not a decorative image asset.
- Keep scoring in src/geometry.mjs independent of React and any future ranking service.
- Ranking returns the top 50 heptagon records plus the current browser's own best. Recompute scores from submitted coordinates on the server; never trust a submitted score. Preserve unrounded scores in score_raw on rounds and records (at least ten decimal places of useful precision) separately from display/ranking score. Backfill existing records from their saved coordinates without changing public scores, names, timestamps or rank. Use a one-use, expiring server round tied to an HttpOnly player cookie. Store one best per browser, rank equal displayed percentages equally, and keep names public only after an explicit registration action. Keep anti-abuse limits and explain browser-local identity. This casual ranking cannot prove that submitted coordinates were placed manually.
- Cloudflare backend lives in cloudflare/index.mjs; keep the Sites starter worker intact. Use npm test and npm run build:cloudflare before npm exec -- wrangler deploy. D1 migrations live in cloudflare/migrations; never commit credentials, .wrangler state or .dev.vars.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
